### السيرفر — **208 اختبار ناجح**
- **الكاشير:** الفاتورة مصدر الحقيقة للفلوس (بتتعمل لما الدور يخلص، ولو الكاشير مقفول بتتسدّد كاش لوحدها)، والدفع المقسوم والباقي والبقشيش، والخصم بحدّ للاستقبال، والمرتجع والإلغاء بسبب، وطرق الدفع، والدرج (فتح، ومصروف، وسلفة، وإيداع، وسحب، وقفل بالعدّ والفرق)، وتقفيل اليوم (Z) بملخّص ثابت.
- **المنتجات والمخزن:** باركود، ومتوسّط تكلفة مرجّح، وشراء وجرد واستهلاك، وتنبيه المخزون.
- **حساب الحلاقين:** نسبة أو يومية أو إيجار كرسي بنفس المعادلة، والعمولة بتتسجّل على سطر الفاتورة وقت الدفع، وقفل الحساب بيمنع الحساب مرّتين.
- **الكروت والأختام والتذكير:** كارت لكل زبون في كل محل (بالموبايل أو بحساب التطبيق)، وملاحظات، وصور قصّات (بتتخزّن على السيرفر وبتتقري بتوكن)، وكارت أختام بمكافأة، وتذكير «بقالك 3 أسابيع».
- **المحل هو السيرفر:** `HUB_MODE`، والسيرفر بيقدّم اللوحة وتطبيق الزبون بنفسه (`STATIC_DIR` و`CUSTOMER_STATIC_DIR`)، ونسخ احتياطية (JSON مضغوط) كل 6 ساعات وبعد التقفيل مع نسخة لفولدر السحابة، واسترجاع، والإشعارات اللي فشلت بسبب النت بتستنّى. ومسارات `/hub` (عناوين الواي فاي والنسخ والاسترجاع) بصلاحية `hub.manage` للمالك.
- migrations من `0007` لـ `0010`، وبتعبّي بيانات المرحلة الأولى القديمة (فاتورة مدفوعة كاش لكل دور خلص، وكارت لكل زبون).

### لوحة المحل — **60 اختبار Vitest**
- **صفحات جديدة:** الكاشير (الفواتير المفتوحة، والدفع، وبيع منتج، والدرج)، وتقفيل اليوم، والمنتجات والمخزن، وحساب الحلاقين، والزباين (بحث، وكارت: ملاحظات وصور وأختام وزيارات، و«وحشونا»). وفي الإعدادات: الكاشير وطرق الدفع والإيصال والأختام والتذكير والنسخ الاحتياطية. والإيصال بيتطبع (80 أو 58 مم).
- **الأجهزة والإعدادات في وضع المحل:** «على واي فاي المحل» بروابط التلفزيون والكشك والكرسي وتطبيق الزبون بـ QR على عنوان الكمبيوتر الحقيقي، وكود الربط بيعرض العنوان ده بدل `app://`.
- **اتجرّب في المتصفّح (2026-11-09):** كل الصفحات الجديدة بتفتح وبتعرض بيانات (الكاشير، والتقفيل، والمنتجات، والحساب، والزباين)، وكارت الزبون (حفظ ملاحظة)، والأجهزة والنسخ الاحتياطية في وضع المحل. الدفع من شاشة الكاشير اتجرّب في جلسة قبل كده (كاش مع مكافأة وبقشيش)، وفي الجلسة دي الدفع اتعمل من الـ API.

### تابلت الكرسي
كارت الزبون قدّام الحلاق: ملاحظاته وآخر صورة وزيارة رقم كام، وملاحظات الجايين، و«صوّر القصّة» (الصورة بتتصغّر على التابلت لحوالي 17 ك.ب قبل الرفع). اتجرّب: ربط وPIN و«التالي» وكارت الزبون ورفع صورة (بملف متولّد، مش كاميرا حقيقية).

### تطبيق الزبون — **27 اختبار**
كارت الأختام في صفحة المحل وفي «حسابي» (ومفتاح «فكّروني لو غبت»)، و«قصّاتي» (مع المسح)، والفاتورة والصور في «دوري»، والمبلغ الحقيقي في «سجلّي». اتجرّب في المتصفّح بمقاس موبايل مع زبون مربوط بكارت.

### برنامج الكمبيوتر — **19 اختبار** (`cd desktop && npm test`)
- **وضعين في أوّل تشغيل:** «الكمبيوتر ده هو سيرفر المحل» (المحل والمالك، وMySQL المتشحونة أو المتسطّبة، وفولدر السحابة) و«اتصل بسيرفر موجود».
- `desktop/src/hub.js`: بيشغّل MySQL (لو متشحونة) وسيرفر نعيمًا بنفس `HUB_MODE` في عمليات جانبية (Electron نفسه كـ Node)، وبيراقبه ويعيد تشغيله، وبيوقّفه نضيف عند الخروج. اللوج في `userData/hub/logs`.
- **الطباعة:** `printHtml` على طابعة الإيصالات المختارة من قايمة «نعيمًا» من غير نافذة، ونافذة الطباعة العادية لو مفيش طابعة مختارة.
- **اتجرّب فعلًا:** تجهيز وتشغيل وإيقاف حقيقي على MySQL موجودة وعلى `mysqld` متشحون (بكلمة سر)، وبملف Electron كـ Node، وتشغيل Electron من غير نافذة في وضع المحل (`npm run smoke:hub`: السيرفر قام، واللوحة اتحمّلت، والجسر موجود، والسيرفر وقف مع الخروج).

### اللي **ما اتجرّبش** (لازم قبل أوّل محل حقيقي)
- الطباعة على طابعة إيصالات حقيقية (الجسر والقياسات بس اتجرّبوا).
- صورة القصّة من كاميرا تابلت حقيقية، وإشعارات «بقالك 3 أسابيع» على موبايل.
- ملفات التثبيت (`npm run dist`) وشحن MySQL داخلها على ويندوز (`desktop/vendor/README.md`)، وصور Docker.
- **نفق Cloudflare** لزباين البيت: **ما اتبنّاش**؛ دلوقتي تطبيق الزبون بيشتغل على واي فاي المحل بس.

### قرارات مفتوحة
- **ملكية رقم الموبايل:** الحساب بيتعمل من غير تأكيد الرقم (OTP)، والكارت بيتربط بالرقم لما صاحب الحساب ياخد دور في المحل. فلو حد سجّل برقم غيره وأخد دور، ممكن يشوف أختام وصور القصّات بتاعة صاحب الرقم. **لازم تأكيد الرقم (SMS أو واتساب) قبل ما الصور تتفتح للزباين**؛ لحد ما يتعمل، فكّر تقفل «قصّاتي» أو تخلّي الربط بكود من المحل.

## التشغيل

```bash
cd server
cp .env.example .env        # وعدّل القيم
npm install
npm run db:setup            # ينشئ قاعدة naeeman ويعمل المحل والمالك من قيم .env
npm run dev                 # http://localhost:4030/api/v1
npm test                    # على قاعدة naeeman_test (بتتمسح بياناتها)
```

- MySQL المحلي: `root` من غير كلمة سر. قاعدة `naeeman` فيها محل ومالك من `db:bootstrap` بس (مفيش بيانات تجريبية). قاعدة `naeeman_test` بتتعمل لوحدها مع الاختبارات.
- البورتات: السيرفر 4030، لوحة المحل 5200، تطبيق الزبون 5201 (`cd mobile && npm run dev`).

## ملاحظات للي هيكمّل
- اكتب بنفس أسلوب الموجود: تعليقات عربية، ESM، Zod، ردود `{success, data}`، المال بالقروش، و`withQueue` لأي تعديل على الطابور (ما تعدّلش `queue_tickets` من برّه الخدمة).
- أي تغيير بيأثّر على الوقت المتوقّع من برّه الطابور (زي حالة حلاق) لازم ينادي `queueService.touch(shopId)`.

- ملفات الـ migrations اللي اتنفّذت ما تتعدّلش؛ أي تغيير = ملف جديد.
- الـ bus جوّه نفس العملية: لو السيرفر اتشغّل بأكتر من نسخة، الشاشات بتعتمد على `?since=` لحد ما يتحطّ Redis pub/sub في `src/queue/bus.js`.
